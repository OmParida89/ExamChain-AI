# ExamChain — Secure, Fair & Intelligent Examinations

---

## 🧠 What is ExamChain?

ExamChain is a full-stack examination platform that solves core problems with traditional MCQ-based exams:

- **Cheating** — Every student receives a uniquely assigned question variant, generated by AI from a shared concept pool. Copying answers between students is structurally useless — and if live demand ever outpaces the recorded variant supply, the system tells the teacher exactly where and with whom.
- **Unfairness** — Scores are normalized into a true percentile rank, so performance is judged relative to peers and weighted by question difficulty — not just raw correct counts.
- **Integrity** — Once an exam is locked, no question can be edited or added. Every question block is chained to the previous one with a SHA-256 hash as a tamper-detection layer.
- **Visibility during the exam, not just after it** — teachers aren't flying blind while students are mid-exam: a live activity view shows who's in progress, who's finished, who ran out of time, and who's been switching away from the exam tab.

## ✨ Features

### 👨‍🏫 For Teachers
- Register/login with full email OTP verification
- Create multiple exams, each with its own shareable 6-character admit code and configurable time limit
- Add questions with a concept tag and difficulty level — AI (via OpenRouter) generates 5 unique variants per question
- **Review and edit AI-generated variants** before they're saved — fix wording or correct answers before they go live
- Lock an exam to freeze its questions permanently
- **Capacity & Drift panel** — see each question's recorded variant capacity against live student demand, with a usage bar and, if demand has outstripped supply, exactly which students ended up sharing an identical variant
- **Live Exam Activity panel** — a real-time-refreshable view of every student's status (in progress / submitted / timed out) and how many times each has switched away from the exam tab
- View a full results dashboard: leaderboard (with tab-switch counts and a late-submission marker), concept-wise weakness analytics, and a one-click release/hide toggle for student-facing scores
- Forgot password flow via OTP

### 👨‍🎓 For Students
- Register/login with college email, exam roll number, and full OTP verification
- Join any exam using a 6-character admit code
- Take the exam with a live countdown timer (server-enforced — refreshing doesn't reset the clock, and never reshuffles which question variant they were given)
- Question navigation dots to jump between questions and track progress
- **Auto-submit when time runs out**, with a clear "⏰ Time's up!" confirmation distinct from a normal manual submission — backed by a short server-side grace window so an honest submission that lands a second or two late over the network is never unfairly zeroed
- **Tab-switch proctoring** — leaving the exam tab is counted and surfaced immediately as an on-screen warning ("⚠️ Tab left: N"), so students know it's being recorded in real time
- See only a confirmation message immediately after submitting — no score is shown until released
- Once a teacher releases scores: view personal correct-answer count and percentile rank — never other students' data

### 📊 Scoring & Fairness
- Each question carries a difficulty weight (1–5), set by the teacher
- Raw performance is calculated as a difficulty-weighted score
- Final rank is a **true percentile** — the top scorer in any exam always lands at exactly the 100th percentile, with ties handled correctly
- A server-side integrity check refuses to serve results if the percentile math ever produces an invalid output, rather than silently shipping wrong numbers
- Percentile calculations only ever consider fully-submitted attempts — an in-progress or abandoned attempt can never skew another student's rank

## 🔐 Security Model

- **Authentication:** JWT-based, with bcrypt password hashing and OTP email verification gating both registration and login
- **Role separation:** Teacher and student accounts are strictly separated — the same email cannot register as both
- **Ownership checks everywhere:** every teacher-facing endpoint (exam details, questions, capacity/drift, live activity, results, release toggle) verifies the requesting teacher actually owns the exam in question — not just that they're *a* teacher
- **Identity from the token, not the request:** a student's identity for starting, submitting, or sending a tab-switch heartbeat is always read from their JWT, never from a client-supplied ID — one student can't act on another's exam attempt
- **Exam locking:** Once locked, no question can be edited, added, or removed via the application — enforced server-side regardless of frontend state
- **Tamper-detection hash chain:** Each question block is hashed together with the hash of the previous block (SHA-256), forming an append-only chain that would visibly break if any question's content were altered after creation
- **Variant assignment, pinned:** each student's question variant is randomly assigned and permanently pinned to their attempt the moment they start — a page refresh can't reshuffle it, and grading always uses the pinned variant, never a value the client could tamper with in the submission payload
- **Capacity-aware:** variant pools are finite by nature; the Capacity & Drift panel makes it visible the moment live demand exceeds what was recorded when the question was written, instead of silently reusing variants
- **Server-enforced timing:** Exam start time is recorded server-side on first load; the deadline cannot be extended by refreshing or replaying requests. Auto-submission is graded against that same server-side deadline (with a small grace window for network latency), never a value the client reports

## 🎨 Design System

ExamChain's visual identity is grounded in the language of physical exam stationery — admit cards, sealed answer sheets, official stamps — rendered through a modern glassmorphic UI with ambient animated backgrounds.

- **Palette:** ink black background, warm paper cream surfaces, brass gold (teacher/primary), muted green (student/success), oxblood red (alerts)
- **Typography:** Fraunces (serif, headings — gives an "official document" feel), Inter (UI text), JetBrains Mono (codes, timers, scores)
- **Signature elements:** the exam code rendered as a perforated admit-card ticket, a rotated "Sealed" stamp badge on locked exams, lettered-circle answer options, and a boxed OTP-style code entry for joining exams

## 🎯 Demo Flow

1. **Teacher** registers, verifies email via OTP, creates an exam with a duration
2. **Teacher** adds a question → AI generates 5 variants → teacher reviews/edits → confirms
3. **Teacher** locks the exam, gets a shareable 6-character code
4. **Student** registers, verifies email, joins the exam using the code
5. **Student** takes the exam with a live timer; switching tabs is counted and flagged on-screen in real time ("⚠️ Tab left: N")
6. **Teacher** (mid-exam, in another session) opens the exam's **Capacity & Drift** and **Live Exam Activity** panels — sees who's still in progress, who's finished, and whether variant demand has exceeded what was recorded when the question was written
7. **Student** either submits manually or lets the timer run out — a timeout auto-submits and shows a distinct "⏰ Time's up!" confirmation instead of the normal one
8. **Teacher** opens Results, sees the leaderboard (correct count, percentile, tab-switch count, and a ⏰ marker on any late submission) plus concept-wise weakness breakdown, releases scores
9. **Student** returns to their results page and sees their correct-answer count and percentile

## 🏆 Origin

This project began as a submission for the **Examinations** theme at FAR AWAY 2026, built around three pillars:

- ✅ **Security** — unique, pinned variants per student, locked exams, tamper-detection hashing
- ✅ **Fairness** — difficulty-weighted, percentile-normalized scoring that only counts real submissions
- ✅ **Intelligence** — LLM-powered question variant generation and concept-level analytics

It has since moved from hackathon prototype toward a real, deployable product with proper authentication, email verification, and a dedicated visual identity — and gained a fourth pillar along the way:

- ✅ **Observability** — a Capacity & Drift indicator that flags when live student demand has exceeded the variant supply recorded at question-creation time, plus a live exam activity view (in-progress / submitted / timed-out status, tab-switch counts) so a teacher can see what's happening *during* an exam, not just read about it afterward.
